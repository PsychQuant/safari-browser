## Context

#256 把 `js` 的成功路徑縮成一次呼叫：結果在 131072 個 UTF-16 單位以內，直接是 `do JavaScript` 的回覆。結果更大時，包裝把它存進頁面，回覆只帶長度與槽的名稱。`js --large`／`--output`、`get`、`snapshot`、`exec` 本來就用這種存進頁面再分塊讀回的做法。

## Goals / Non-Goals

目標：存進頁面的路徑，每個呼叫的結果只有它自己讀得到；分塊讀取的每一塊都可驗證；兩者都不增加成功路徑的往返次數。

非目標：不加協作式取消的檢查點；不回收硬終止的呼叫留在頁面的槽（#193）；不把頁面槽當成安全邊界；不改 `js` 一般路徑的協定（#256 的內嵌包裝宣告 `r`、`m`，會遮住頁面上同名的全域變數，這裡沒有動，#259）。

## Decisions

### 一個頁面物件，一個名稱

槽是 `window.<key> = { text, len, err, started, threw }`。結果、長度、`--large` 包裝記錄的執行期錯誤，以及「程式碼開始了」「程式碼丟了錯」兩個證據（見〈執行證據〉）都在同一個物件上，所以一個呼叫只有一個名稱要清除、一個名稱可能出錯。`len` 未定義就是「沒有存入」的標記（`JSWrapper.lenUnsetSentinel`），頁面導走、槽不見與程式碼沒有解析成功在 `lengthScript` 上讀成同一個值；要分辨它們，讀 `progressScript`。

### 名稱由誰取

CLI 取名（`ResultSlot.make()`，UUID）：`--large` 需要在程式碼執行之前就知道名稱，才能預先設定槽並在失敗後讀錯誤。

頁面取名（內嵌包裝的 `SB1:BIG:<len>:<key>`）：內嵌包裝的文字不能含每次不同的名稱，否則每一個 `js` 的腳本文字都不同，daemon 的編譯快取對最常見的指令就失效。名稱由計數器、時間與亂數組成，CLI 在使用前以 `ResultSlot.isValid` 檢查（`__sbr_` 加 8 到 64 個 `[0-9a-z]`），因為名稱會被貼進後續腳本；不合格的回覆是錯誤，不讀、不再執行程式碼。

頁面可以改寫 `Date`、`Math.random` 或計數器 `window.__sbn`（假計時器、隱私擴充功能），所以名稱不依賴它們合格：計數器放最前面並強制成無號整數，時間與亂數放在 `try` 裡、只會增加名稱的長度，非 `[0-9a-z]` 的字元一律丟掉，最後接固定尾巴保證長度夠。第一版沒有這樣做，頁面把時間與亂數都換成常數時名稱短於 8 個字元，被自己的檢查擋下，結果留在頁面上而且清不掉。

名稱不是祕密，也不是認證邊界：同一頁面的腳本讀得到它。它防的是這個 CLI 的不同呼叫互相讀到對方的結果。

### 包裝不在使用者的範圍裡宣告變數

使用者的程式碼被放在包裝函式裡執行，包裝裡任何 `var` 都會遮住頁面上同名的全域變數，使用者讀到 `undefined` 而沒有任何錯誤。第一版的存入腳本宣告 `var s`、`var r`，大型路徑的 catch 宣告 `var s`，內嵌的命名宣告 `var k`；審查在頁面有全域 `s`、`r`、`k` 時重現（`JSON.stringify(s)` 變成 `undefined`），而以前（兩個固定名稱）的大型路徑沒有這個問題。現在存入腳本把使用者的運算式當成**引數**傳給存入函式（在 `do JavaScript` 的最上層求值），大型包裝的 catch 以自帶參數的小函式把丟出的值轉成文字、寫進 `window.<key>.err`（不宣告變數），內嵌的命名放在自己的函式裡。測試在頁面有全域 `s`、`r`、`k`、`e`、`m` 時跑每一種包裝。

### 分塊回覆的形狀

`<end>:<text><U+001E>`。`end` 是這一塊實際結束的位置：若塊的邊界落在 surrogate pair 中間，提早一個單位結束，下一塊從 pair 的開頭開始。結尾標記不是空白，所以 runner 拿掉結尾換行（連結果自己的最後一個換行、還有 `\n\r` 的怪癖）與 daemon 路徑拿掉所有結尾空白，都碰不到結果本身（這是 #255 在真機量到的行為）。讀取端按 Unicode scalar 解析，因為塊開頭的組合字元會與 `:` 黏成同一個字素簇。長度要精確相等，標記要在，位置要落在預期的範圍內。

讀取腳本在槽被換掉、被移除或長度與預期不同時回空，讀取端把空當成錯誤。以前讀一個不存在的全域變數會回空，被當作一個空的塊接在結果後面，結果就靜默變短。

### 整體結果的最後一個換行

分塊讀取以前每一塊都經 runner 拿掉結尾換行，所以結果的最後一個換行不見。現在每一塊完整，讀完後只拿掉**一個**結尾換行，印出來的位元組與以前相同；塊與塊之間的換行不再被拿掉（那是以前的缺陷）。

### 讀取：每次都分塊

#256 的 `SB1:BIG` 以前先做一次普通讀取，回空才退到分塊並印警告。空的回覆分不出「太長」與「槽不見了」，普通回覆也無法驗證，所以現在一律分塊。131073 到 262144 單位的結果仍是一塊，往返次數不變；更大的結果多幾次讀取。

### 孤立 surrogate

存入前 `toWellFormed()`，換成 U+FFFD，不報錯（#257 的 B7）。osascript 會靜默丟掉孤立 surrogate，U+FFFD 長度相同且能活下來。沒有 `toWellFormed` 的 Safari 保留孤立 surrogate，讀取端會看到長度不符而報錯。

### daemon

沒有改 daemon。名稱每次不同，所以槽的讀取與清除腳本在 daemon 的編譯快取裡每次都是新的項目。這些腳本很小，只出現在少見的路徑：snapshot 與 `get text` 是先做普通讀取、空或不合法才退到分塊；`js --large` 是明確要求的。快取有界（256 項，LRU，#170），所以最壞情況是少見的指令把幾個項目擠出去，不是無界成長。#192 為此加了暫時編譯政策與一個新 RPC（含舊 daemon 的相容退回），這個 change 判斷不值得。若之後量到實害再加。

### 導頁

頁面在長度讀取與第一塊之間被換掉時，槽不見了。這與 #82 的其他導頁是同一件事：網址與執行前不同就回報導頁（stderr 一行、結束碼 0、沒有值）；網址沒變才是傳輸不完整的錯誤。`js --output` 在沒有結果可寫時失敗並保留原檔（以前導頁後把檔案截成零位元組、結束碼 0，真機量到：main 與 #256 都是 0 位元組）。

### 逾時後不清除

逾時表示頁面的主執行緒忙著，清除會再等一個逾時，使用者等同一個錯誤的時間變成兩倍。逾時後不試清除；槽留在頁面直到導走（#193）。

## 執行證據（#257 B2 的後半，#260）

#257 的 B2 是「刪除一般路徑的狀態機，只留給仍存進頁面的路徑」。仍存進頁面**而且執行使用者程式碼**的路徑是 `js --large`／`--output`；`SB1:BIG`（內嵌包裝的大結果）也是，但它的回覆就是結果，沒有第二次嘗試，所以沒有「重跑」的問題，它的殘留見下面。其餘路徑讀的是頁面上已有的東西，沒有程式碼要重跑。`--large`／`--output` 原本靠「長度未設定」的哨兵加網址檢查分辨「沒跑」與「跑了」：一個沒有結果的第一次嘗試，會讓第二種形式被送出；程式碼已經執行、頁面被換成同一個網址（`location.reload()`）時，兩次嘗試都看不到結果，程式碼被執行兩次（真機上 `main` 與 #256 各量過三次，伺服器都數到兩次）。

做法是只加**一個**證據，而不是 #192 的四狀態：包裝在使用者的程式碼之前，先在槽上標記 `started`，而且只標記已經存在的槽。再加一個旗標 `threw`，由 catch 在做任何可能失敗的事之前先設。結果（`text`／`len`）與錯誤（`err`）本來就在槽上，所以這兩個欄位足以讓 `progressScript` 回答，CLI 依答案決定：

| 從槽讀到 | 意思 | 命令 |
|---|---|---|
| `idle:undefined`（槽在、沒有 `started`） | 包裝沒有開始（沒有解析成功），什麼都沒跑 | 試另一種形式；兩種都沒有就是語法錯誤 |
| `threw:`（槽在、`threw`） | 程式碼丟了錯 | 讀得到訊息就報 `JavaScript error: <訊息>`；讀不到（訊息太長讀不回、轉成文字失敗）也是錯誤，不是空結果 |
| `started:<長度>`（槽在、有 `started`、沒丟錯） | 程式碼開始了且沒有丟錯 | 長度 0 或 1 且讀回來是空：結果是空的，或只有一個換行（輸出一向丟掉的那一個）；長度 2 以上但沒讀回來（長度讀取遺失）：失敗，不是空結果；`started:undefined`（沒有結果、沒有錯誤，不是包裝會產生的狀態）：失敗，不再執行 |
| `gone`（槽不在） | 頁面被換掉，程式碼可能跑過 | 網址變了就是導頁（#82）；網址沒變（或讀不到網址）就失敗，說不知道程式碼有沒有跑，不再執行 |

不認得的回答一律讀成 `gone`，也就是永遠不會再執行任何東西的那一個：冒號後面不是 `undefined` 也不是長度的回答是損壞的，讀成 `gone`；只有精確的 `idle:undefined` 才能讓另一種形式被送出。

只送本機編得過的那一種形式（`JSSyntaxHint.formsToTry`，與一般路徑相同）：語句形式的程式碼不會先送一個不能解析的運算式形式，所以那個形式不會剛好遇到在兩次往返之間被換掉的頁面（第二次審查找到的窗口：以前會是失敗，可用性退化，不是重跑）。兩種都編不過、或程式碼超過 1,000,000 單位時，兩種都試，運算式先，這時由槽上的標記擋住第二次執行。

被丟出的值不論是什麼都記成錯誤，文字與一般路徑相同（`throw null` 是 `JavaScript error: null`）。轉成文字可能自己丟錯（`Symbol('x')` 沒有隱含的字串轉換、`Object.create(null)` 沒有 `toString`、getter 會丟錯、`toString` 回傳的不是字串），所以分三步保護並且永遠得到一個字串，而且不在使用者的範圍裡宣告任何東西。訊息在頁面裡切到 16384 個單位（加 `…`），因為更長的單次回答會回空（#1），回空就會被讀成「沒有錯誤」；`threw` 旗標讓連「訊息讀不回來」都還是錯誤。錯誤的回覆有 `E:` 前綴，並且按 Unicode scalar 比對前綴，所以訊息為空（`throw ''`）、或以組合符號開頭（與 `:` 融成一個 Character）的錯誤都不會被讀成沒有錯誤。

這與 #192 不同的地方：沒有 prepared／running／done／error 四個狀態，也沒有「done 之後狀態遺失」與「error 之後細節遺失」兩種專用的錯誤。`done` 對應 `len` 已設定，`error` 對應 `err`／`threw` 已設定；結果或錯誤被換掉或消失時，報成「頁面被換掉」或「傳輸不完整」的失敗。

#192 其餘沒有帶的：協作式取消的檢查點（這個專案裡取消等於結束 worker，檢查點沒有會被執行到的路徑，依審查對 `MCPPersistentRunner` 的閱讀，未另行驗證）、daemon 的暫時編譯政策與新 RPC（#257 沒有決定這兩項）、孤立 surrogate 報錯（B7 決定換成 U+FFFD）、每塊帶呼叫識別與請求的結尾位置（槽名已唯一；讀取檢查 `end > offset`、`end <= total`、精確長度與結尾標記）。

### 仍然成立的限制（記錄，不是已解決）

- **先丟錯再導頁**：錯誤記在舊文件的槽裡，導頁後讀不到，網址變了就報成導頁（結束碼 0、沒有值）。有測試釘住，所以改變它是刻意的。
- **頁面被換掉但程式碼其實沒跑**：例如頁面自己的計時器剛好在預設與存入之間 reload。CLI 觀察不到「程式碼開始了」，只觀察到「槽不在」，所以報「不知道有沒有跑」，並且不再執行（安全方向的誤報）。
- **`--url` 目標的有界重新解析（#79）**：`do JavaScript` 跑完之後才丟出 -1719／-1728，而且重新解析到同一視窗的另一個分頁時，存入腳本（含使用者程式碼）會被整段重送。需要程式碼自己在執行途中關掉所在分頁；沒有在真機驗證，也不在這個 change 的範圍。
- **`SB1:BIG`**（內嵌包裝的大結果）的第二次嘗試與一般路徑相同：兩種形式都編不過、回覆遺失而網址沒變時仍可能執行兩次（#255 記錄過，`main` 就如此）。

## Risks / Trade-offs

- 硬終止或取消的呼叫會把槽留在頁面，直到頁面導走。以前固定名稱會被下一次呼叫覆蓋，所以最多留一份；現在每個孤兒留一份，大小與結果相同。#193 追蹤回收。還有兩種不是硬終止的情況也會留下：無旗標的 `js` 在讀取途中使用者切了分頁（清除被身分檢查擋下），以及內嵌回覆的槽名不合格時（CLI 不敢清）。
- `SB1:BIG` 的結果大於一塊（262144 單位）時，往返次數比 #256 的一次普通讀取多：N 個單位要 ceil(N/262144) 次讀取（1,048,576 單位是 4 次）。#256 的普通讀取在真機最大到 1 MiB 成功；這裡換來可驗證。耗時見真機量測。
- 沒有 `toWellFormed` 的舊 Safari，孤立 surrogate 會讓分塊讀取報錯而不是靜默丟字。
- 頁面上留下一個數字 `window.__sbn`（計數器）。
- 每個呼叫的槽腳本（存入、長度、每一塊、清除；`--large` 另有預設與錯誤讀取）都含槽名，所以各占 daemon 編譯快取（256 項、LRU）一項。一次呼叫新增：結果讀回來時 4 加塊數個項目，結果為空或程式碼丟了錯時 6 個，語句形式再多 1 個，所以迴圈裡跑幾十次 `--large --output` 就會把整個快取換過一輪。快取有界，不影響正確性，對暖啟動的影響沒有量測。
