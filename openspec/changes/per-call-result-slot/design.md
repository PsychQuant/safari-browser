## Context

#256 把 `js` 的成功路徑縮成一次呼叫：結果在 131072 個 UTF-16 單位以內，直接是 `do JavaScript` 的回覆。結果更大時，包裝把它存進頁面，回覆只帶長度與槽的名稱。`js --large`／`--output`、`get`、`snapshot`、`exec` 本來就用這種存進頁面再分塊讀回的做法。

## Goals / Non-Goals

目標：存進頁面的路徑，每個呼叫的結果只有它自己讀得到；分塊讀取的每一塊都可驗證；兩者都不增加成功路徑的往返次數。

非目標：不處理 `--output` 在程式碼導頁後的行為；不加協作式取消的檢查點；不回收硬終止的呼叫留在頁面的槽（#193）；不把頁面槽當成安全邊界；不改 `js` 一般路徑的協定。

## Decisions

### 一個頁面物件，一個名稱

槽是 `window.<key> = { text, len, err }`。結果、長度、`--large` 包裝記錄的執行期錯誤都在同一個物件上，所以一個呼叫只有一個名稱要清除、一個名稱可能出錯。`len` 未定義就是「沒有存入」的標記（`JSWrapper.lenUnsetSentinel`），頁面導走、槽不見與程式碼沒有解析成功都讀成同一個值，`--large` 靠它分辨「沒跑」與「跑了但是空」，與以前相同。

### 名稱由誰取

CLI 取名（`ResultSlot.make()`，UUID）：`--large` 需要在程式碼執行之前就知道名稱，才能預先設定槽並在失敗後讀錯誤。

頁面取名（內嵌包裝的 `SB1:BIG:<len>:<key>`）：內嵌包裝的文字不能含每次不同的名稱，否則每一個 `js` 的腳本文字都不同，daemon 的編譯快取對最常見的指令就失效。名稱由時間、亂數與計數組成，CLI 在使用前以 `ResultSlot.isValid` 檢查（`__sbr_` 加 8 到 64 個 `[0-9a-z]`），因為名稱會被貼進後續腳本；不合格的回覆是錯誤，不讀、不再執行程式碼。

名稱不是祕密，也不是認證邊界：同一頁面的腳本讀得到它。它防的是這個 CLI 的不同呼叫互相讀到對方的結果。

### 分塊回覆的形狀

`<end>:<text><U+001E>`。`end` 是這一塊實際結束的位置：若塊的邊界落在 surrogate pair 中間，提早一個單位結束，下一塊從 pair 的開頭開始。結尾標記不是空白，所以 runner 拿掉結尾換行（連結果自己的最後一個換行、還有 `\n\r` 的怪癖）與 daemon 路徑拿掉所有結尾空白，都碰不到結果本身（這是 #255 在真機量到的行為）。讀取端按 Unicode scalar 解析，因為塊開頭的組合字元會與 `:` 黏成同一個字素簇。長度要精確相等，標記要在，位置要落在預期的範圍內。

讀取腳本在槽被換掉、被移除或長度與預期不同時回空，讀取端把空當成錯誤。以前讀一個不存在的全域變數會回空，被當作一個空的塊接在結果後面，結果就靜默變短。

### 整體結果的最後一個換行

分塊讀取以前每一塊都經 runner 拿掉結尾換行，所以結果的最後一個換行不見。現在每一塊完整，讀完後只拿掉**一個**結尾換行，印出來的位元組與以前相同；塊與塊之間的換行不再被拿掉（那是以前的缺陷）。

### 讀取：每次都分塊

#256 的 `SB1:BIG` 以前先做一次普通讀取，回空才退到分塊並印警告。空的回覆分不出「太長」與「槽不見了」，普通回覆也無法驗證，所以現在一律分塊。131073 到 262144 單位的結果仍是一塊，往返次數不變；更大的結果多幾次讀取。

### 孤立 surrogate

存入前 `toWellFormed()`，換成 U+FFFD，不報錯（#257 的 B7）。osascript 會靜默丟掉孤立 surrogate，U+FFFD 長度相同且能活下來。沒有 `toWellFormed` 的 Safari 保留孤立 surrogate，讀取端會看到長度不符而報錯。

### daemon

沒有改 daemon。名稱每次不同，所以槽的讀取與清除腳本在 daemon 的編譯快取裡每次都是新的項目。這些腳本很小，只出現在少見的路徑：snapshot 與 `get text` 是先做普通讀取、空或不合法才退到分塊；`js --large` 是明確要求的。快取有界（256 項，LRU，#170），所以最壞情況是少見的指令把幾個項目擠出去，不是無界成長。#192 為此加了暫時編譯政策與一個新 RPC（含舊 daemon 的相容退回），這個 change 判斷不值得。若之後量到實害再加。

## Risks / Trade-offs

- 硬終止的呼叫會把槽留在頁面，直到頁面導走。以前固定名稱會被下一次呼叫覆蓋，所以最多留一份；現在每個孤兒留一份，大小與結果相同。#193 追蹤回收。
- `SB1:BIG` 的結果大於一塊時，往返次數比 #256 的普通讀取多（那條路徑以前的普通讀取在真機上最大到 1 MiB 成功）。代價換來可驗證；真機驗收時量。
- 沒有 `toWellFormed` 的舊 Safari，孤立 surrogate 會讓分塊讀取報錯而不是靜默丟字。
- 頁面可以覆寫 `Math.random` 或 `Date`。名稱帶一個計數，所以即使如此兩個呼叫也不會取到同一個名稱；計數是頁面上留下的一個數字 `window.__sbn`。
